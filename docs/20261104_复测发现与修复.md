## 二、复测暴露的问题与修复

### 1. 安全模式没有真的跳过更新（P1）

`SetSafeMode(true)` 把 `updateDisabled` 置真，但 `checkForUpdates` 第一段就
`a.updateDisabled = false`，随后照常打网络。探针实测：

```
进入设置页前：safeMode=true updateDisabled=true  updateChecking=false
触发检查后：  safeMode=true updateDisabled=false updateChecking=true
```

于是 README 承诺的「不检查更新、标题栏不出现更新图标」全部不成立；有新版时还能装。

修复：`checkForUpdates` / `installUpdate` / 标题栏更新控件三处都先判 `safeMode`。
测试 `TestSafeModeSkipsUpdateCheck` 已验证「移除守卫就会失败」。

### 2. 单实例锁取得太晚（P1）

原顺序：迁移 → 日志 → 重置偏好 → **打开数据库（含历史裁剪）** → 建 App → **取锁**。
第二个进程（双击图标、`app.exe --page=task`）会先真的删一批历史记录、写同一个日志文件、
库里记一条启动事件，然后才发现自己不是主实例。

修复：取锁提到迁移与开库之前；`--reset-settings` 挪到取锁之后（否则运行中的实例会把
删掉的设置再写回来），并在已有实例时明确提示「请先退出」。取锁只读设置里的一个字段，
不构造 App。

### 3. `--reset-settings` 直接删文件（P1）

改成 `os.Rename` 备份为 `settings.json.bak-<时间>`，失败才退化为删除；`Reset` 返回备份
路径写进审计日志。测试覆盖「备份存在且内容完整」「文件不存在时不报错」。

### 4. 性能断言 flaky（P2）

`ropeCost*10 > strCost` 只跑 50 次（约 200µs）。关键事实：**这台机器上连续 2000 次
`time.Now()` 读到同一个值**，200µs 的区间整段落在同一刻度，读数在 0 与几十微秒间跳。
放大到 2000 次（约 10ms）后，实测比值稳定在 48~78 倍，单核连跑 30 次零失败。

页面内「对比」按钮同一问题：`ropeRuns=500` 时可能算出 0 ns 并显示「快 > 1000 倍」。
改 2000 轮 + 「无法精确测量」兜底，现在显示的是真实数字（约 60 倍）。

### 5. 迁移非原子（P2）

原先 `data.db`、`-wal`、`-shm` 各自独立搬、失败就跳过。只搬走主库而把 `-wal` 留下，
等于丢掉 WAL 里已提交的事务——用户看到数据回退，且没有任何报错。

修复：三件套作为一组，任一失败把已搬的回滚。测试用「同名目录占住目标路径」制造失败，
并验证过「去掉回滚代码该测试会红」。

### 6. 日志没有体积上限（P2）

只按天切分，`--log-level=debug` 常开一天能写几百 MB。新增单文件 16MB 上限与分片
（`app-<日期>.2.log`…，每天最多 64 片），`prune` 同时认得分片名（原实现会把分片当成
「别人的文件」永久留下）。诊断包按 32MB 预算、优先带最新日志。

### 7. 4 处协程无 panic 兜底（P3）

生成新项目、目录选择、图标选择、选背景图 —— 统一补 `logging.Recover`。生成协程尤其
重要：panic 会留下半成品目录且日志空白。

### 8. 诊断包导出卡主线程（P3）

`VACUUM INTO` + 压缩 + 日志打包全在主线程（1000 条任务实测 17ms，库越大越久）。
改为后台协程，**先在主线程取 `basicInfoText()` 与库指针再进协程**（App 字段只在主线程
读写，直接跨协程读会构成数据竞争）。

### 9. 基准口径混淆（P3）

`BenchmarkFrame` 每轮新建 Tester，测的是冷帧（3.4ms），文档里的「一帧」容易被误读成
日常渲染成本。新增 `BenchmarkSteadyFrame`（130µs）与 `BenchmarkSteadyFrameSettings`
（2.6ms），注释里写明两者区别。

## 三、两处我要更正自己的判断

- **快捷键允许绑裸字母不是问题**：mygo 的 `Shortcut` 文档写明焦点元素先消费——文本输入
  会「编辑」字母键，所以绑 `r` 在输入框里不会误触发。`setShortcut` 只拦 Esc 是合理的。
- **设置页没有常驻动画**：两处 `BreathingDot` 只在「正在检查/下载更新」分支里，正常状态
  不驱动重绘，不存在「设置页常驻烧 CPU」。

## 四、验证

```bash
go vet ./...                                   # 通过
go test ./... -count=1                         # 全绿（含 30s 端到端生成 + 编译）
go test ./... -count=1 -cpu 1                  # 单核模拟 CI，全绿
go test -race ./internal/view/ ./internal/logging/ ./internal/apppath/ ./internal/settings/
python scripts/snapshot-template.py --check    # 125 文件一致
```

生成器实测：复制 125 个文件 → 裁剪后 78 个（0.1.6 新增 cli/诊断/快捷键等文件后基数变大，
裁剪比例不变）。

## 五、仍未做（需单独一轮）

   而这个页面用户可能一辈子不打开。要挪成「首次进入时帧外构建」，需处理 `ui.Render`
   不能在帧内调用的约束。
2. **设置页分区折叠**：2.63ms/帧、2560 次分配，热点全在框架 `commitElement` 与文字 shaping，
   纯元素数量驱动。默认折叠「数据与诊断」「窗口与关闭」可显著降低，但要改 `kit.Section`。
3. **启动时静默检查更新**：现在只有进设置页才检查，用户不点设置就永远不知道有新版本。
