# 2026-11-04 · 页面开发配套：私有状态、异步加载、页面脚手架

> 目标（用户原话）：开发者做功能开发时**不用关心日志、DB、配置，不用关心页面的创建和
> 销毁**；底座提供主题、字号、背景图、自动更新等基础能力；开发者只关注新页面的业务。
>
> 对照这个标准做了一轮评估，补了三块真正会「漏到底座之外」的配套：A 页面私有持久化、
> C 新增页面脚手架、B 异步数据加载。下面按落地顺序记录。

---

## 一、评估结论（先看结论）

底座（字体 / 主题 / 背景 / 自动更新 / 单实例 / 窗口 / 托盘 / 日志 / DB 连接 / 页面生命周期 /
页头 / 滚动 / 间距）已经做到「页面不用管」。真正会漏的三处：

| 缺口 | 以前的做法 | 现在 |
|---|---|---|
| 页面级持久化（筛选条件、草稿） | 改 `settings.Settings`（还要配设置页 UI），或给 `store` 加表 + 迁移 | `a.Prefs()`，自动落到 `page_pref` 表，库不可用时退化为内存 |
| 异步数据（加载中 / 失败 / 迟到结果） | 每页自己起 goroutine + 回主线程 + 代次号 | `pageAsync` + `op.View(c, t, render)` |
| 新增菜单页面 | 手写页面文件 + 手改注册表字面量（id 字符串多处重复） | `go run ./scripts/newpage -id ...`（页面 id 抽成常量） |

仍然刻意不做：通用 CRUD 框架、页面级设置页 UI、运行期注册表（`internal/scaffold` 的菜单裁剪
依赖「字面量 + AST」，这条不能破）。

## 二、A：页面私有持久化（`a.Prefs()`）

### 2.1 存储

`internal/store` 新增 `page_pref` 表，`schemaVersion` 1 → 2：

```sql
CREATE TABLE IF NOT EXISTS page_pref (
    page TEXT NOT NULL,       -- 页面 id（菜单注册表里的 id）
    key  TEXT NOT NULL,       -- 页面自己约定的键
    value TEXT NOT NULL,      -- 调用方序列化后的值（视图层用 JSON）
    updated_at TEXT NOT NULL,
    PRIMARY KEY (page, key)
)
```

版本号改成「**只在更高时更新**」（`ON CONFLICT ... DO UPDATE ... WHERE excluded > current`）：
老库升级会从 1 升到 2；用旧版打开新库（降级）不会把版本写回去。

### 2.2 API（`internal/view/prefs.go`）

```go
p := a.Prefs()                 // 绑定当前页（a.page），不用再写页面 id
var f orderFilter
if p.Get("filter", &f) { ... } // 没存过 → false，f 保持零值
p.Set("filter", f)             // JSON 序列化后写库
p.Delete("filter")
```

要点：

- **页面 id 取当前页**：页面函数与 `onEnter/onLeave` 里 `a.page` 就是这一页，省掉重复的字符串；
- **内存缓存**：`Set` 先写内存再写库；`Get` 先查内存（页面每帧都读同一个键，不能每帧查库）；
- **库不可用（`a.store == nil`）**：自动退化为纯内存，行为与「任务列表走内存」一致；
- **脏数据容错**：历史 JSON 解析失败只记一条 WARN 并按「没存过」处理——页面加字段后不该被旧值卡死；
- **边界**：应用级偏好（主题、字号、快捷键）仍归 `settings.json`，不进这张表。

### 2.3 测试

`internal/store/store_test.go`：读写/覆盖/按页面隔离/删除/重开仍在/版本升级/空键拒绝。
`internal/view/prefs_test.go`：JSON 往返、换 App 实例（重启）仍能读、无库退化内存、
跨页隔离、脏 JSON 当未设置、不可序列化值返回错误。

## 三、C：新增页面脚手架（`scripts/newpage`）

### 3.1 用法

```bash
go run ./scripts/newpage -id orders -label 订单管理 -group 工作台 -icon Table
# 可选：-policy fresh|pinned（默认 cached）、-dir <项目根>（默认当前目录）
```

产出：

1. `internal/view/page_orders.go`：`const pageOrdersID = "orders"` + `func (a *App) ordersPage(...)`
   的最小骨架（卡片 + 空态提示），只有 ui 与 kit 两个 import；
2. `internal/view/registry.go`：在指定分组的 `items` 最前面插入
   `{id: pageOrdersID, label: "订单管理", icon: icons.Table, build: (*App).ordersPage},`。

### 3.2 实现要点（`internal/pagegen`）

- **只做文本插入 + gofmt**：用 `go/parser` 定位 `navRegistry()` 返回值 → 找到分组 →
  找到 `items` 的 `{` → 按缩进插入一行，再 `format.Source` 整份文件。保留的分组、注释、
  空行一字不动，生成的 diff 最小；注册表仍然是字面量，`internal/scaffold/regcut.go` 照常裁剪。
- **参数校验**：id 只允许小写/数字/连字符；分组必须存在（错误里列出可用分组）；图标名必须在
  `internal/ui/icons` 里有导出；重复 id（含手写的字符串 id）直接拦住；页面文件已存在则不动。
- **失败不留半成品**：所有校验在写盘前完成；写注册表失败会回滚刚创建的页面文件。
- **模块路径从 `go.mod` 读**：生成的页面 import 用当前模块的 `internal/ui/kit`，所以在
  「新建项目」生成的工程里同样可用（模板快照包含 `internal/pagegen` 与 `scripts/newpage`）。
- **测试**（`internal/pagegen/pagegen_test.go`）：插入到指定分组/置顶组、策略字段、
  非法 id/空标题/未知分组/未知图标/重复 id/缺 go.mod、插入后 gofmt 结果、页面文件模板。

## 四、B：异步数据加载（`pageAsync`）

### 4.1 用法

```go
op := pageAsync(a, "rows", func() ([]row, error) {
    return loadRows() // 在后台协程里跑：只读数据，不要碰 ui
})

op.View(c, t, func(rows []row) {
    kit.Card(c, t, func() { /* 用 rows 渲染 */ })
})
```

行为：首次绘制发起加载；**每次重新进入本页**自动重载；加载中显示占位卡片；失败显示错误卡片 +
「重试」；只采纳最新一次结果；`load` 里 panic 会被兜成一次「加载失败」，不崩窗口。

需要「刷新」按钮时：`op.Reload()`（下一页重建时生效）；`op.Value() / op.Loading() / op.Err()`
可在同一页里做额外判断。

### 4.2 线程模型（为什么要这么写）

mygo 是即时模式 UI：界面只能在主线程构建。后台协程**不直接改状态**，而是把结果放进
`asyncState.pending`（`sync.Mutex` 保护），然后调用 `a.requestFrame()`
（`Window.Invalidate` 自身跨线程安全）。下一次 `View` 在主线程 `drain()`：取走、校验代次、
落到状态里再绘制。这样：

- 没有跨线程改 App 状态（`go test -race` 也干净）；
- 「加载完成 → 采纳」有明确的一帧边界，离屏测试可以稳定地逐帧推进；
- 切页后迟到的结果按代次丢弃。

### 4.3 演示页

「功能演示 → 异步数据（加载/重试）」：`page_async.go`，带「下次加载失败 / 下次返回空列表」
两个开关，演示加载中、失败重试、空态、进入即刷新。`asyncDemoDelay` 供测试调成 0/小值。

### 4.4 测试（`internal/view/async_test.go`）

首帧显示加载中 → 数据出现；失败卡片 + 重试恢复；空列表空态；切走再回来重新加载；
过期代次结果丢弃；load panic 转错误。

## 六、边界与后续

- [ ] `page_pref` 没有清理策略（表会随页面/键增多缓慢增长）。可在「设置 → 数据与诊断」加一个
      「清理页面状态」入口，或在 `onDestroy` 里按需删。
- [ ] `pageAsync` 不取消已经在跑的后台加载（结果会按代次丢弃，但 goroutine 会跑完）。
      对长任务可在 `load` 里自行接收 `context.Context`。
- [ ] 页面级「设置项」还没有统一入口（目前页面私有配置用 `a.Prefs()` 自己做 UI；应用级配置
      仍集中在设置页）。如果很多页面都需要，可再做「页面设置」注册机制。
