## 三、逐轮记录

### 3.1 侧栏图标对齐与展开/收缩（`a83c76b`）

**需求**：品牌头、菜单项、底部「设置」三处图标中心要在同一条竖线上；点击品牌图标整体收起/展开，收起时只留图标 + 悬浮提示；状态要持久化。

**做法**：

- 侧栏由 `ui.Sidebar` / `ui.SidebarItem` 改为**自定义渲染**（品牌头 + 可滚动菜单区 + 固定底部设置项）。原因：只有自己掌控布局，才能同时满足「三处图标同轴」与「两态（展开/收缩）共用一套数据模型」。
- 对齐公式：菜单/设置图标 16px、品牌图标 20px，品牌内缩回退 `(20−16)/2 = 2px`，于是两者中心都落在 `内容内缩 + 8px`。
- 收缩态 64px rail：图标居中、悬浮 `Tooltip` 提示菜单名，分组之间用短分割线分隔。
- 持久化：`settings.json` 新增 `sidebarCollapsed`，切换即原子写盘，下次启动恢复。

**测试**：新增 `TestSidebarCollapsed`（收缩态不再出现品牌文字/分组标题）、`TestSidebarCollapsedInitFromSettings`（从偏好初始化）。

### 3.2 箭头、呼吸空间与滚动条（`ed89038`）

三个反馈逐条对应：

| 反馈 | 根因 | 处理 |
|---|---|---|
| 下拉箭头太小 | 用的是 10px 文字字形 `▸/▾` | 换成 14px Lucide 线性 SVG（`iconChevronRight/Down`） |
| 悬停/选中背景「占太满」 | `Scroll` 横向 padding 为 0，行自身的横向 padding 只内缩**内容**、不内缩**背景**，于是高亮铺满整宽 | 把横向内缩移到 `Scroll` 上，行背景随之变成「药丸」 |
| 滚动条碍眼 | 框架默认绘制滚动条 | `t.Scrollbar = t.Scrollbar.Alpha(0)`——**只是画不出来，滚轮/触控板照常滚** |

收缩态同步处理：整行作为命中区，内部图标药丸居中，悬停只给药丸着色，左右留白。

### 3.3 对齐 javafx 的留白模型（`99b6334`）

第二轮调完仍被指出「左右空隙还是太大」，于是直接读 `bestuav-javafx` 的实现：

- `src/main/java/com/bestuav/components/layout/SidebarNavContainer.java`
- `src/main/resources/css/sidebar.css`、`menu-item.css`

关键差异在**留白模型**：

| 维度 | 我们（改前） | javafx（正确参考） | 最终采用 |
|---|---|---|---|
| 高亮水平边距 | 12px（加在 Scroll 上 → 悬浮窄条） | 4px（`.sidebar{padding:4}` → 近满宽） | 内缩移到侧栏根容器，仅 4px |
| 行内边距 | 上下 6px | 上下 10px | 上下 10px |
| 项间行距 | 4px（挤） | 8px | 8px |
| 分组标题 | 曾试过加文件夹图标 | 纯文字 | **纯文字**，且文字左边缘与菜单**图标**对齐 |

顺带修掉一个硬 bug：`settingsItem` 写在 `Scroll` 外面却漏了横向内缩，导致「设置」图标比菜单图标左移一截（错位）。现在菜单项/设置项/分割线共用同一内缩基准。

### 3.4 背景图、内容区重构、标识集中、多实例（`e9fd539`）

**（1）背景图 + 分区透明度**

- `settings.json` 新增 `backgroundImage` / `menuOpacity` / `contentOpacity`（默认 0.80 / 0.88，合法区间 0.2–1.0，越界与 0 值回落默认——老文件没有这两个字段，反序列化就是 0）。
- 设置页「背景」区：选择图片（系统原生文件对话框）、恢复默认（清图 + 复位两个滑块）、两个独立不透明度滑块（无背景图时禁用）。
- 层级：背景图铺满最底层 → 侧栏浮层 / 内容区浮层 → 控件面 → 文字与强调色。
- **踩坑**：mygo 的绝对定位元素是在该父节点**所有常规流兄弟之后**绘制的（`ui/paint.go`），所以「背景图 Absolute + 主体常规流」会让背景盖住界面。改成反向：背景图作常规流第一个子元素（`Fit(ui.Cover).Fill()`），主体用 `Absolute().Top/Left/Right/Bottom(0)` 铺满叠在上面。

**（2）内容区三段式布局（新文件 `internal/view/content.go`）**

1. 固定页头（52px，不滚动）：左标题 + 右侧自定义图标工具条。工具条用 `ScrollHorizontal + Shrink(1)`——按钮少时按内容宽度**靠右**，空间不足时被压缩到可用宽度从而**横向滚动**（滚动条已全局透明）。
2. 分割线槽位（3px）：常态 1px 浅线；轻量任务执行时**同一槽位**画 `ui.Progress`。槽位高度固定，所以进度条出现/消失不会让下方内容跳动。
3. 可滚动内容区（`ui.Scroll` + 内边距 24/28）。

**两条分割线严格同高**：侧栏与内容区都是 `Space(1)=4px + headerHeight=52px` → 都落在 **y=56**。这条约束由 `TestDividersOnSameRow` 用离屏渲染的真实像素断言守住（各取一列，在 y∈[50,60] 窄带内找最暗行，断言相等）。

**轻量任务接口**：`a.startLightTask("导出")` → 后台 goroutine 推进进度（`mygo.RunOnMain` 改状态）→ `a.endTask()`。重绘依赖 main 注入的 `SetInvalidator(win.Invalidate)`。

**（3）产品标识集中 `internal/appmeta`**

`Name` / `Title` / `Identifier` 一处定义，`main.go`、`sidebar.go`、`settings.go`、设置页、测试全部引用；Go 代码里已无「量子科学」「com.bestuav.quantum」硬编码。注释里写明与 `mygo.json` 的对应关系（改产品名要动两处：appmeta + mygo.json）。

**（4）单/多实例开关**

`settings.AllowMultiInstance` 默认 `false`。`main` 启动时：未开启 → `RequestSingleInstanceLock()`，取锁失败即转发参数后退出；`OnSecondInstance` 里 `win.Show()` 唤出已有窗口。开启 → 跳过取锁，多开互不干扰。设置页「启动」区用 `ui.Switch`，标注**需重启生效**（锁在进程启动时获取）。

**（5）顺手修的配置路径 bug**

`settings.path()` 一直把 `settings.json` 直接写在用户配置目录根下（注释却写 `%APPDATA%\bestuav-mygo\`）。改为按 `appmeta.Name` 分子目录，并加**旧路径一次性迁移**（`legacyPath()`）：新位置不存在而旧位置存在时，读旧文件 → 归一化 → 写入新位置，用户偏好不丢。

### 3.5 控件面半透明：解决「组件遮挡背景图」（本轮，随本文档提交）

**现象**：设置背景图后，概览卡片、设置卡片、按钮等整块不透明，把照片挡成白板。

**根因**：这些组件都用 `t.Surface` 着色且不透明；背景图在最底层，中间任何不透明面色都会挡住它。逐个改组件不现实——`ui.Button`、`ui.Table`、`ui.Segmented`、`ui.Slider`、自绘卡片全都在用主题色。

**解法**：mygo 的 `c.Theme()` 返回**每帧共享的同一份 `*Theme`**。于是每帧开始时调用 `App.applyBackdropTheme(t)`，把主题里的「控件面」相关颜色统一降透明度，所有从主题取色的组件一次性跟随。

透明度不是同一个值，而是分层推导（内容区不透明度记作 `p`）：

| 层级 | 公式 | `p=0.54` 时 |
|---|---|---|
| 内容区浮层 | `p` | 0.54 |
| 悬停底 | `p + (surface−p) × 0.35` | 0.62 |
| 控件面（卡片/按钮/输入框） | `p + (1−p) × 0.5` | 0.77 |
| 按下态 | `surface + (1−surface) × 0.5` | 0.88 |

**为什么悬停底要比控件面「虚」**：分段控件/页签的选中项是用 `Surface` 画的。第一版把悬停底设成与控件面同透明度，结果选中项与轨道同为 0.77，「跟随系统」只剩一圈边框、几乎看不出选中的是哪个。改成 悬停 0.62 < 控件面 0.77 后，选中项明显更实。

**必须用绝对 alpha 赋值**：`ui.RGBA(r,g,b,a)` 而非 `Color.Alpha(a)`。后者是**乘算**，而 Theme 实例跨帧复用，会逐帧越来越透明；绝对赋值幂等，且关掉背景图后界面能立刻恢复完全不透明。

**刻意不参与调整的颜色**：`Text` / `TextMuted` / `Border` / `Accent`。文字与描边半透明会直接伤可读性；强调色承载选中态语义（表格选中行、开关、进度条），保持不透明。若日后希望选中行也透出背景，把 `Accent` 加进 `applyBackdropTheme` 即可。

**顺带修掉一个测试隐患**：`NewApp()` 会读开发机真实的 `settings.json`，于是「我把侧栏收起了」这件事让 `TestHomePage` / `TestSidebarFolders` / `TestDividersOnSameRow` 集体变红——测试结果依赖本机状态，属于典型的不确定源。已把构造拆为 `newApp(s *settings.Settings)`，`NewApp()` 退化为 `settings.MustLoad()` 的包装，测试统一走 `newTestApp() = newApp(settings.Default())`。

**新增测试**：

- `TestBackdropThemeAlphas`：锁定层次 `浮层 < 悬停 < 控件面 < 按下 ≤ 1`，并要求控件面比浮层至少实 0.05、又不实于 0.95（否则遮住背景）。
- `TestNoBackdropKeepsOpaque`：无背景图时四种面色必须 alpha=255，且两个浮层不透明度为 1。
