# 20261029 基本信息改为设置页弹窗，移除「个人中心」菜单

## 一、背景与目标

「个人中心 → 基本信息」里全是**系统与运营信息**（应用标识、运行环境、页面缓存、数据库/日志
路径、配置文件位置），不属于日常业务操作，长期占着一个菜单分组不划算。

王工的要求：**并入设置页、用一个按钮打开弹窗查看，并移除「个人中心」菜单分组**。

方案取舍：

| 决策点 | 结论 | 理由 |
| :--- | :--- | :--- |
| 按钮 vs 设置页里的一块区域 | **按钮 + 弹窗** | 信息量大（5 组、二十来行），铺在设置页会把「改偏好」这条主线冲淡；弹窗只在需要时出现 |
| 弹窗内部：长滚动 vs 分页签 | **分页签**（应用 / 环境 / 缓存 / 数据与日志 / 配置） | 先按「固定高度 + 内部滚动」实现，离屏截图发现**滚动区把文字从中间截断**（半行字，看起来像渲染坏了）。改页签后每屏只显示一组，高度可控，也更好定位 |
| 弹窗高度 | 每个页签一个高度（132/186/236/236/96） | 统一高度会让只有 4 行的「应用」页签留出大片空白 |

## 三、截图暴露的真实缺陷：弹窗半透明

用**本机真实偏好（含壁纸 + 分区透明度）**重拍截图时发现：弹窗面板是**半透明**的，
背后的设置页文字直接透过弹窗正文，完全无法阅读。

根因：`applyBackdropTheme` 为了「让壁纸从内容区透出」，把 `t.Background` 的 alpha 降到
内容区不透明度（如 0.73）；而 `ui.Modal` 的面板用 `panel.Background(t.Background)` 绘制
→ 弹窗跟着半透明。这个缺陷在加背景图的用户那里**一直存在**（系统的「系统通知」弹窗、
关闭询问弹窗都有），只是信息稀疏时不易察觉。

修法：新增 `modalPanel(c, t, &open, fn)`，在**构建弹窗期间**把 `t.Background` 临时换成
不透明色，构建结束立即还原（`defer`）。依据是「主题颜色在构建元素时被复制进元素，而不是
绘制时现读」，所以这段临时修改只影响弹窗自身：已构建好的页面、以及之后构建的其他浮层
（重量级遮罩、toast）都不受影响。四个弹窗统一走它。
