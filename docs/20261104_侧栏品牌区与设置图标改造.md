## 一、需求（原话）

1. 设置菜单的图标应该改成**小齿轮**，意思更明确；
2. **品牌区域**一般不能点击、或者点击回首页；但品牌区又不能点的时候，「收侧栏」就没地方处理；
3. 所有改动都要**兼顾「新建项目」功能**。

## 二、图标：把「太阳」换成齿轮

**问题**：侧栏底部「设置」、首页快捷入口用的 `icons.Gear` 实际是「圆 + 八条放射短线」，
16px 下读起来是太阳/亮度，容易被当成「外观 / 主题」。渲染对比后确认，用户说的「小齿轮」
指的就是真正的带齿轮廓。

**做法**：换成 8 齿 + 空心轴的齿轮（单条外轮廓 path + 一个中心圆，stroke 1.8）：

- 外轮廓不是手写的：按「齿顶角 15°、齿根角 8°、外径 9.6、根径 7.7、8 齿」用脚本算出的
  `A`（圆弧）+ `L`（齿侧斜线）路径，保证八个齿等距、左右对称；
- 描边 1.8（而不是 2）：16px 下齿缝不会被糊死；
- 中心圆 r=3 留出空心轴，与其它线性图标的「空心」风格一致。

**取舍**：也对比过 Lucide / Feather / Tabler 的 settings 图标——它们多是 6 齿，16px 下更像
雪花或花朵；8 齿配空心轴的齿形在小尺寸下最容易被读成「齿轮」。

## 三、品牌区与侧栏开关：一件区域只做一件事

### 3.1 原设计的问题

品牌头整块点击 = 收起/展开侧栏。于是同一块区域有两种互斥语义：

- 用户按通用习惯点 logo，期待「回首页」，结果侧栏收了；
- 收缩成 64px 图标栏后没有文字，品牌图标如果继续兼任「展开」，用户点 logo 时无法预期
  是回首页还是展开；
- 想给品牌区加「回首页」就没有位置了。

### 3.2 方案比较（含第一版被否掉的做法）

| 方案 | 品牌区 | 收/展开方式 | 结论 |
|---|---|---|---|
| A | 点击 = 切换侧栏 | 品牌区 | 现状，语义冲突 |
| B | 点击 = 回首页 | 品牌行右端小图标按钮 | 展开态直观；但收缩态（64px）塞不下第二个图标，会破坏「品牌图标与菜单图标同轴」 |
| C1 | 点击 = 回首页 | 底部**一行「收起侧栏」文字** + Ctrl/Cmd+B | 否掉：看起来像新增了一个菜单项，视觉上多一条导航 |
| C2 | 点击 = 回首页 | 展开态：品牌行右端 **«** 图标；收缩态：底部 **»** 图标；Ctrl/Cmd+B | 采用 |

### 3.3 采用 C2 的理由

- **品牌区只做一件事**：点它回首页（`HomeID: "home"`，悬浮提示「返回首页」）；`HomeID` 为空时
  退化成不可点的静态标识。悬停底色只包住「图标 + 文字」的小药丸，不再整行高亮，避免和
  右侧开关共用一块大高亮、看起来像同一个控件。
- **开关只有一个图标、不占菜单行**：
  - 展开态挂在品牌行**右端**（页头图标按钮的规格：32×28 命中区、悬停才出现圆角底色），
    这是 VS Code / JetBrains 一类工具窗最常见的「收起侧栏」位置；
  - 收缩后 64px 放不下第二个图标（品牌图标必须与菜单图标同轴），开关落到**底部、设置上方**，
    只剩一个 **»** 图标药丸，与「设置」同一列；
  - 图形用双箭头 « / »：16px 下比「带箭头的小面板」干净得多（后者缩到 1x 只是一个带痕迹的
    小方块），也与分组标题右侧的单个开合箭头区分得开。
- **键盘路径**：新增动作 `view.toggle-sidebar`，默认 `Ctrl/Cmd+B`。它不指向任何页面，
  属于「窗口级动作」，因此在设置页可以改绑、可以禁用；禁用后开关的提示里就不再出现键位
  （不提示一个按了没反应的键）。

为什么不用「品牌行右侧 + 收缩态也放品牌行」：64px rail 里 brand 20px + 按钮 28px 虽能勉强
塞下，但品牌图标中心会偏离菜单图标中心（这是当初花了一轮才对齐的几何约束）；而「展开」
换到顶部又会让同一动作在两种状态下换位置。

## 四、实现要点

### 4.1 shell（`internal/view/shell/sidebar.go`）

- `SidebarOptions` 新增：
  - `HomeID string`：品牌按钮点击后前往的页面 id；空 = 不可点；
  - `ToggleHint string`：侧栏开关悬浮提示的附加文本（当前键位，如 `Ctrl+B`）。
- 品牌行拆成两个按钮：`brandButton`（图标 + 产品名，点击回首页）与 `sidebarToggle`
  （纯图标，点击收/展）。`brandButton` 自带 6px 左右内边距，`brandHeader` 的行内边距
  回退同样的值，品牌图标中心仍与菜单图标中心对齐（`brandInset` 的几何约束不变）。
- `brandTitleMax = 120`：品牌名过长时省略，避免把右侧开关挤出 220px 宽的侧栏。
- 抽出 `actionRow`：菜单项与底部固定项共用同一套「展开态整行 / 收缩态图标药丸」的命中区
  与高亮规则（这份样式以前在 `navRow` 与 `navFooter` 里各抄了一遍，曾抄漏过一次横向内缩）。
- `sidebarToggle`：28 高 × 32 宽、次要文字色（不抢菜单强调色）、`Focusable + Role(RoleButton)
  + Label`——收缩态没有文字，读屏与 `ui.Tester` 靠 `Label` 找到它，Tab 到它也能用
  Enter/Space 触发。
- 分割线位置不变：展开态底部只剩「设置」；收缩态开关在**下方**分割线之后，不影响
  「侧栏分割线 y = 4+52」这条被 `TestDividersOnSameRow` 用像素钉住的约束。

### 4.2 快捷键（`internal/shortcut` + `internal/view/shortcuts.go`）

- `shortcut.Action` 新增 `ToggleSidebar bool`（与 `Page` / `Refresh` 并列，三种效果互斥，
  由 `TestActionsHaveExactlyOneEffect` 守住）；
- 动作表新增 `{ID: "view.toggle-sidebar", Label: "收起/展开侧栏", ToggleSidebar: true, Def: "cmd+b"}`；
- `runShortcut` 分发到 `App.toggleSidebar()`；
- `App.saveSidebarCollapsed()` 统一「写回偏好 + 防抖落盘」：侧栏开关（shell 翻转指针后回调）
  与快捷键（App 自己翻转）走同一条持久化路径；
- `rebuildShortcuts` 顺带刷新 `a.sidebarToggleHint`，避免每帧重新解析键位字符串。

## 五、兼顾「新建项目」

「新建项目」生成的新工程来自 `internal/scaffold/testdata/template` 里的**源码快照**。这次改动
落在共享骨架里，因此：

1. **必须重跑快照**：`python scripts/snapshot-template.py`，否则生成出来的项目还是旧的品牌区
   行为与太阳图标。CI 用 `--check` 检查过期。本次已刷新。
2. **快捷键裁剪安全**：生成器只删「`Page` 指向已裁掉页面」的动作（`internal/scaffold/shortcut.go`）。
   `view.toggle-sidebar` 没有 `Page`，因此勾掉任何分组都会保留它——新项目即使只剩首页，
   也还能用键盘收/展侧栏。
3. **模板断言**：`internal/scaffold/shortcut_test.go` 的样例动作表与 `scaffold_test.go` 的
   产物断言都加上了这条动作，防止以后有人把它改成导航动作、被裁剪逻辑顺手删掉。
4. 新项目若想「品牌区不可点」：把 `internal/view/app.go` 里的 `HomeID: "home"` 删掉即可，
   shell 会退化成静态品牌头（不注册 cursor/tooltip/焦点）。
