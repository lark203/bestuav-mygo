# 20261029 缓存表格随字号自适应 + 移植三个官方示例

## 一、缓存表体高度随字号自适应

**问题**：上一版把表体高度写死为 `160`（= 字号 14 下的整 5 行）。应用支持 11–22px 字号，
字号一变行高就变，`160` 就不再等于整行数，表体底部会出现被切一半的行。

**改法**（`internal/view/basicinfo.go`）：

```go
// 行高 = 上下内边距 12 + 一行文字的近似行高
func cacheRowHeight(t *ui.Theme) float32 { return t.FontSize*1.3 + 12 }

// 能完整放下的行数：3..5，取整；同时把行距算进去
// body = n*rowH + (n-1)*2 ≤ avail  ⇒  n ≤ (avail+2)/(rowH+2)
func cacheRowsFit(t *ui.Theme) int { ... }

func cacheBodyHeight(t *ui.Theme) float32 { return n*rowH + (n-1)*2 }
```

- 页签高度也动态化：`cacheTabChrome(104) + cacheBodyHeight(t)`；
- `cacheTabMaxHeight = 292` 是上限（最小窗口 520 高时，弹窗内容区约 480，扣掉标题/页签/按钮的余量）；
- 字号变大 → 行高变大 → 能放的行数自动从 5 降到 4、3，**始终整行**；字号小则封顶 5 行。

> 踩坑：第一版按 `avail/rowH` 取整，**忘了算行距**，字号 19 时总高刚好越界 3.5px
> （`TestCacheTabHeightFitsAnyFont` 逮住）。改成 `(avail+2)/(rowH+2)` 后，11–22px 全部通过。

**测试**：`TestCacheTabHeightFitsAnyFont` 遍历 11..22px，断言
①整行数在 3..5；②`cacheBodyHeight` 恰好等于「整行数×行高+行距」；③总高不超过上限。

## 二、移植 mygo 官方示例（第一批 3 个）

从 `github.com/egoist/mygo/examples` 中挑选**纯 UI、无外部依赖**的三个，改造为菜单页：

| 页面 | 来源 | 改造要点 |
| :--- | :--- | :--- |
| 加载指示器 | `examples/loading`（101 行） | 29 种指示器 + 尺寸/颜色/缓动/端点开关。动画由插件内部 `Painter.AnimationFrame` 驱动，页面无需请求重绘；选项行套卡片、指示器网格自适应换行 |
| 笔记（富文本） | `examples/notes`（341 行） | `ui/richtext` 编辑器 + 格式工具条（粗/斜/下划线/删除线/代码/链接/列表/引用/代码块）+ Markdown 复制。落盘位置从示例自建的 `MyGo Notes/notes.json` 改为本应用配置目录的 `notes.json`；去掉应用级菜单，改页面内工具条；编辑器放进固定高度容器 |
| Markdown 聊天 | `examples/markdown-chat`（184 行） | `ui/markdown` 的 `Stream`/`View` 双态渲染，按词/句/行/段流式吐出，列表跟随末尾并平滑滚动。示例用 `win.Update` 推帧，我们拿不到窗口对象，改用注入的 `a.requestFrame()` + `mygo.RunOnMain`；无窗口/单测环境直接一次性给全文 |

菜单新增分组「官方示例」（注册表 `registry.go`）：加载指示器（默认缓存）、笔记（缓存 +
页头复制按钮）、Markdown 聊天（`keepFresh`，离开即销毁，回来是干净会话）。

**新增/改动文件**

- 新增 `internal/view/page_loading.go`、`page_notes.go`、`page_markdown_chat.go`
- `internal/view/app.go`：三组演示状态（`loading*` / `chat*` / `note*`）与默认值
- `internal/view/registry.go`：新分组与三个条目
- `internal/view/basicinfo.go`：表体高度自适应
- 测试：`TestOfficialDemoPages`（三页都能渲染）、`TestNotesPersist`（写入/读回 notes.json，
  测试注入临时路径，不碰开发机真实笔记）、`TestCacheTabHeightFitsAnyFont`

## 四、遗留

1. **`blackhole`（GPU 黑洞特效）未搬**：需带 3 个 `.kage` 着色器资源（`go:embed`）与拖拽/滚轮
   输入处理，约 300 行；本批先交付 3 个无风险页面，它适合单独一批做。
2. **剩余候选**（`code-editor` / `text-input` / `flyout` / `effort-slider` / `piano` 等）的规模与
   依赖已整理进 README「Roadmap」，其中 `piano` 依赖 `mygo/audio`，无头环境无法验证。
3. **演示页的固定高度**（笔记/聊天用 `Height(520)`/`Height(430)`）：因为应用的内容区是可滚动的，
   而编辑区/会话区需要确定边界。若将来给 `shell.Content` 增加「不自适应滚动」的页面模式，
   可去掉这些魔法数字。
