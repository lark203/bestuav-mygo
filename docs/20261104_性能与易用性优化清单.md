# 性能与易用性优化（0.1.6）

> 背景：项目功能已经齐了，但长期使用暴露出几类问题——「每帧做一次本可以只做一次的事」、
> 「该异步/防抖的同步 IO」、以及几个支持类功能缺口（诊断、命令行、快捷键、开机自启）。
> 本文记录这一轮 20 项优化的依据、改法与验证方式。

## 一、先量后改：改之前的基线

| 指标 | 数值 |
|---|---|
| 一帧 `View`（1100×720，离屏 CPU 光栅化） | 10.9 ms / 4.4 MB / 515 次分配 |
| `navGroups()` 单次 | 9.9 µs / 6 KB / 20 次分配，每帧被调用 ~13 次 |
| 启动常驻 / 峰值内存 | 80 MB / 114 MB（无背景图） |
| 空闲 CPU | 启动后不再增长（按需重绘，✅） |
| 带 6000×4000 背景图时的常驻 | **190 MB**（原图解码 96 MB） |

结论：没有架构级问题；问题集中在重复构建、同步大 IO、以及缺「支持类」能力。

## 二、逐项清单

### 性能

1. **菜单注册表一次性构建 + `id` 索引**
   `navRegistry()` 每次调用都重建 5 个分组 30 余个 item，而它被侧栏投影、页头标题、
   页头工具条、闲置淘汰每帧各查一次。改为 `navAll()` 里 `sync.Once` 构建切片与
   `map[string]navItem`；`navGroups()` 的 shell 投影也缓存。
   ⚠️ `navRegistry()` 必须保持「直接 return 字面量」——生成器靠 AST 在这里增删菜单。
   验证：`TestRegistryLookupAllocations`（`pageByID`/`navGroups`/`navAll` 均 0 分配）、
   `BenchmarkNavLookup`（100 ns / 0 alloc）。

2. **背景图异步解码 + 限宽**
   原来 `os.ReadFile` + `ui.DecodeBitmap` 在主线程全尺寸解码：6000×4000 的照片
   解成 RGBA 要 96 MB，选图瞬间界面卡住。改为后台 goroutine 里「解码 → 面积平均缩到
   2560 宽 → `ui.NewBitmap` → 主线程换图」，并 `debug.FreeOSMemory()` 回收临时内存。
   失败时设置页显示原因，加载中显示「加载中…」。用代次号丢弃迟到的旧结果。
   验证：`bgimage_test.go`（缩放/颜色/4:2:0 快路径/坏文件）；实测 6000×4000 图
   常驻内存 **190 MB → 99 MB**。

3. **设置写盘防抖 300 ms + 退出补写**
   拖动字号/不透明度时每帧都会 `persist()`，原来直接 `Save()`（临时文件 + rename），
   一秒几十次。改为 `time.AfterFunc` 攒批，`OnBeforeQuit → FlushSettings()` 兜底。
   验证：`TestSettingsSaveDebounced`、`TestSettingsFlushOnQuitKeepsLastChange`。

4. **更新检查超时 + 节流**
   `Updater.Check(context.Background())` 没有超时，断网时可能卡到 TCP 超时；
   且每次进设置页都重查。改为 15 s 超时 + 自动检查 10 分钟节流（手动按钮不受限）。

5. **每帧小分配**
   首页 KPI/趋势数据提到包级变量；任务表排序结果按「排序键 + 行数 + 行版本」缓存
   （缓存放进 `pageState.data`，不污染 `App`）；侧栏的 `map[bool]string{...}` 换成 if。

6. **闲置销毁降到 1 Hz，且不销毁当前页**
   顺带修掉一个潜在问题：停留在一个页面上超过 TTL（默认 15 分钟）时，页面会被自己
   的闲置淘汰销毁，表现为「滚动位置/表单突然重置」。验证：`TestEvictSkipsCurrentPage`、
   `TestEvictThrottled`。

7. **缓存上限**
   字表缓存（`letterWords`/`kernedWords`）与柔光位图缓存（`glowBmp`）原来只增不减，
   而界面里会出现数字滚动、任务名、时间戳这类不断变化的文本。加上限（1024/256），
   超限整体清空——重建很便宜，比泄漏可控。

8. **库计数合一条 SQL**：`Stats()` 原来 4 条 `COUNT`，合成一条（同一快照、一次往返）。

9. **历史数据保留策略**
   `task` / `app_event` / `license_record` 只增不减。启动时按「任务 1000、事件 90 天且
   2000、授权 200」裁剪；删除后空闲页占比 ≥1/4 才 `VACUUM`。
   验证：`TestPrune`、`TestPruneEventAge`、`TestBackupAfterPrune`。

10. **首帧不等数据库**
    启动时 `AttachStore` 同步灌演示数据 + 读任务/授权 + 统计（都是磁盘 IO）。改为
    `AttachStoreAsync`：后台读、`RunOnMain` 应用。窗口更早出现。

### 易用性

11. **命令行参数**：`--version` / `--page=` / `--reset-settings` / `--safe-mode` /
    `--log-level=`。Windows 的 GUI 子系统程序没有控制台，`--version` 前先
    `AttachConsole(ATTACH_PARENT_PROCESS)` 接回启动它的终端。
    单实例模式下第二次启动的 `--page` 会转发给已运行实例并唤出窗口。

12. **全局快捷键**：`Ctrl/Cmd+1..5` 跳页、`Ctrl/Cmd+,` 设置、`F5` 刷新当前页、`Esc` 关弹窗。
    刷新 = 重新进入页面（keepFresh 先销毁），保留缓存页面的表单。

13. **开机自启**：设置页开关，走 `mygo.App.SetOpenAtLogin`（Windows Run / macOS 登录项 /
    Linux XDG autostart）。失败回滚 UI 并提示，避免「界面开着、系统里没生效」。

14. **诊断包与目录直达**：设置页「数据与诊断」→ 打开配置目录 / 日志目录 / 导出诊断包。
    诊断包 = `settings.json` + 近三天日志 + `VACUUM INTO` 的数据库快照 + 环境信息 +
    说明文件。此前「复制全部信息」只有文本，支持人员拿不到日志与库。

15. **托盘场景的任务完成通知**：窗口不可见时发系统通知（固定 ID，后一条替换前一条），
    点击通知唤回窗口；窗口可见时不发（界面里已有彩带）。

16. **「忽略此版本」持久化**：存进 `settings.json` 的 `ignoredVersion`，重启后不再提示；
    手动检查仍会显示。

17. **数据/日志目录改为本机目录**：配置（settings.json）留在 roaming；
    `data.db` 与 `logs/` 迁到本机数据目录（Windows `%LOCALAPPDATA%`、Linux `~/.local/share`、
    macOS Application Support）。旧位置自动迁移（只在新位置为空时搬，不覆盖）。
    动机：Windows 域环境/OneDrive 会把 `%APPDATA%` 连同 SQLite 的 `-wal`/`-shm` 一起同步，
    可能锁库、拖慢登录。

18. **启动期警告写日志**：托盘创建失败、图标设置失败、设置解析失败等原来用 `println`
    打到 stderr，GUI 打包后没有控制台等于丢失。改为 `logging.Warn/Errv`；同时修掉
    JSON 日志里重复的 `app` 字段。

### 工程化

19. **CI**（`.github/workflows/ci.yml`）：`gofmt -l`、`go vet`、`go test`（Linux + Windows）、
    `python3 scripts/snapshot-template.py --check`。模板快照与主工程漂移会直接失败——
    生成器随包发的是快照，过期会生成旧代码。
20. **性能基线**：`internal/view/bench_test.go` 的 `BenchmarkFrame` / `BenchmarkNavLookup`，
    README「十四、性能与体积基线」记录量级与「别退回去」的几条坑。

## 三、改之后

| 指标 | 改前 | 改后 |
|---|---|---|
| 一帧 `View`（离屏） | 10.9 ms / 4.4 MB / 515 allocs | **3.4 ms / 4.1 MB / 431 allocs**（不含背景图） |
| 菜单查询 | 9.9 µs / 6 KB / 20 allocs | **100 ns / 0 allocs** |
| 带 6000×4000 背景图常驻 | 190 MB | **99 MB** |
| 空闲 CPU | 不增长 | 不增长 |
| 测试全量 | 35 s | ~35 s（新增 ~40 个断言） |

> 注：一帧耗时前值来自「默认配置 + 用户背景图」的场景，后值来自 `newTestApp`（无背景图），
> 两者不是严格同条件；README 里的基线表以 `BenchmarkFrame` 为准。

## 四、需要人工确认的点

1. **开机自启**：开发构建（`go run`）在 macOS 上需要 `.app` bundle，可能失败并提示；
   Windows/Linux 可直接验证注册表 / `~/.config/autostart` 项。
2. **任务完成通知**：需把窗口关到托盘（关闭行为设为「最小化到托盘」）再跑任务。
3. **目录迁移**：首次启动新版本时，旧 `%APPDATA%\bestuav-mygo\data.db` 会搬到
   `%LOCALAPPDATA%\bestuav-mygo\`；迁移后旧文件不再保留（rename）。
4. **命令行**：`--reset-settings` / `--safe-mode` 会影响真实数据，建议先在测试账号下验证。
