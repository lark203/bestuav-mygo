# 20261029 修复基本信息「缓存」页签：按钮被文字盖住 + 列表被截断

## 一、现象

王工截图反馈两点：

1. 缓存页签里**「销毁非常驻缓存」按钮与说明文字重叠**——实际上被盖住的是**底部的按钮行**：
   提示文字「滚动内容区后切走再切回…」直接压在「刷新环境」按钮上。
2. **缓存的页面展示不全**：只列 5 行，后面用一句「另有 7 个缓存页面未列出」带过。

## 二、根因（读代码 + 截图确认）

| 问题 | 根因 |
| :--- | :--- |
| 文字盖住按钮 | 页签内容区是**固定高度**（`basicTabHeights[2] = 236`），而缓存页签的内容（说明行 + 表头 + 5 行 + 「另有 N 个」+ 提示行）**超过 236**。mygo 的普通容器**不会裁剪溢出内容**，超出的部分就画到了兄弟节点（底部按钮行）上 → 视觉重叠 |
| 列表被截断 | 上一版为了「不超高」而硬编码 `basicCacheShowRows = 5`，多出来的只显示计数——用户要的是**全部展示 + 表格内部滚动** |

## 三、修法

1. **结构上兜底：给页签内容区加 `Clip()`**
   任何页签内容万一超高，也只会在自己的框内被裁掉，**不可能再画到按钮上**。
   ```go
   ui.Column(c).Width(basicInfoWidth).Height(a.basicTabHeight()).Clip().Children(...)
   ```
2. **缓存页签改成「固定表头 + 表体独立滚动」**
   - 表头单独渲染（`pageCacheHeader`），不随表体滚动；
   - 表体 `ui.Scroll(c).Height(cacheRowsHeight)` 承载**全部**缓存页行（`pageCacheBody`），
     去掉 `basicCacheShowRows` 与「另有 N 个未列出」；
   - `cacheRowsHeight = 160` = 5 行整（行高 30 + 行距 2）→ **在行边界处截断，不出现半行**；
   - 页签高度 `236 → 264`，容下「说明行 + 表头 + 表体」。
3. **顶部一行信息合并**：原来底部还有一句「滚动位置…归零」，与顶部说明重复且多占一行
   （正是它被裁成半行）。合并为一句「缓存页切回保留状态（含滚动位置）；闲置或「不缓存」页离开即销毁。」，
   并在右侧加「共 N 个」计数药丸——表体只露 5 行，用它告诉用户「还有更多，可在表内滚」。

## 四、验证

| 项 | 结果 |
| :--- | :--- |
| `go build ./...` / `go vet ./...` | 通过 |
| `go test ./...` | 全通过 |
| 新增用例 | `TestBasicInfoCacheTabListsAll`：把所有页面标记为已缓存后渲染，「缓存」页签必须列出**每一个**页面，且**不得**再出现「未列出」字样 |
| 离屏渲染（全部 14 页已缓存） | 修复前：提示行被裁半行并压在「刷新环境」上；修复后：顶部一行（说明 + 共 14 个 + 按钮）无重叠，表头 5 列对齐，5 行整行显示，表格与底部按钮之间留白正常 |
| 产物清理 | 临时截图测试与 `tmp-shots/` 已删除并 `ls` 复核 |

## 五、限制与遗留

1. **表体滚动无法在无头环境验证**：`ui.Tester` 没有滚轮/拖动 API，只能确认真实渲染的静态
   构图（行数、对齐、无重叠）。「表内能滚」依赖 `ui.Scroll` 的既有机制——本应用侧栏菜单、
   页面内容区、虚拟列表（10000 行装在 360px 高的表里）都在用同一套，风险低。
   **需真机把鼠标放到表格上滚一下确认。**
2. **页签高度仍是手写常量**（`basicTabHeights`）：这是「固定高度 + Clip」方案的前提，改内容
   时要顺手调数字；好处是切换页签时弹窗高度稳定、不会跳变。mygo 暂无内容测量 API。
3. 若将来缓存页行高随字号变化（设置页可调字号），`cacheRowsHeight = 160` 会不再等于「整 5 行」，
   可能出现半行——届时把行高也纳入计算（`(行高+行距)*n`）。
