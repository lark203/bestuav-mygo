# 20261029 架构分层重构 + 统一间距/等宽 + 滚动条策略

## 一、背景与问题

王工提出 5 点问题，逐条对应根因如下：

| # | 现象 | 根因（实测/代码确认） |
| :--- | :--- | :--- |
| 1 | 侧栏滚动条隐藏，但**内容区也没有滚动条** | `internal/view/app.go` 每帧执行 `t.Scrollbar = t.Scrollbar.Alpha(0)`，把**全局** Theme 的滚动条颜色透明化。mygo 的滚动条颜色只有主题级字段，没有单容器开关，所以这一行把侧栏与内容区一起关掉了 |
| 2 | `view/` 下 20 个文件平铺，架构级与业务级混在一起 | 早前所有代码都塞在 `package view`：`sidebar.go`/`content.go`（架构骨架）、`ui_kit.go`（自研组件）、`icons.go`（图标资产）、`home.go`/`task.go`…（业务）同级，改骨架无从判断影响面 |
| 3 | 内容区间距不统一，新页面要自己算空隙 | 留白是**每个页面自己写**的：`Padding(0,0,4)`、`Padding(16,0,4)`、`Padding(20,0,4)`、`Padding(10,0)`、`Padding(16,0,0)` 共存（4/10/16/20 四种区块间距）。内容区的 `Scroll` 只给了 `Padding(24, 28)`，区块之间没有任何统一间距 |
| 4 | 同一行组件大小不一（首页 KPI、任务页卡片） | 用 `Row + Grow(1)` 排卡片。flex 的 `Grow` 只分配**剩余**空间，各卡片基础宽度仍由内容决定，文字长短不同就长出不同宽度 |
| 5 | README 与实际结构脱节 | 文档里写的还是重构前的文件路径与「滚动条统一透明化」的旧策略 |

## 二、方案

### 2.1 分层（Go 的包 = 目录，所以按目录分层）

```
internal/
├── ui/                 # 自研 UI 资产层：与业务无关、可被任意层复用
│   ├── icons/          #   SVG 图标集（icons.Home / icons.Refresh …）
│   └── kit/            #   设计系统：layout.go（间距规格）+ kit.go（通用构件）
├── view/
│   ├── shell/          #   架构骨架：sidebar.go + content.go + layout.go（低频改动、全局影响）
│   ├── page_*.go       #   业务页面（前缀显式标出「业务层」）
│   ├── app.go          #   App 状态 + View 分发 + 装配（把业务塞进 shell 的回调）
│   ├── registry.go     #   菜单/页面/工具条注册表 + navGroups 桥接
│   ├── header.go       #   页头工具条（依赖注册表类型，故留在 view）
│   ├── overlay.go      #   窗口级浮层（弹窗 / toast / 遮罩 / 彩带）
│   └── pagelife.go     #   页面生命周期
└── appmeta/ settings/ license/ crypto/ tasks/   # 既有业务包，未改动
```

依赖方向（单向，无环）：

```
view → view/shell → ui/kit → mygo/ui
view → ui/kit、ui/icons
```

**为什么 shell 不 import view**：侧栏需要读写「当前页 / 折叠态 / 分组折叠表」。若 shell 直接
接收 `*App`，就必须 import view → 与 view import shell 形成环。因此改为注入**指针状态**：

```go
type NavState struct {
    Page      *string           // 点击菜单项直接写回 App.page
    Collapsed *bool             // 点击品牌头翻转 App.sidebarCollapsed
    Folded    map[string]bool   // 直接就是 App.groupFolded
}
```

再加一个 `OnCollapseChange func(bool)` 回调让 App 持久化偏好。这样 shell 完全不知道 App 的
存在，包依赖保持单向。

**为什么业务页不拆成子包**：页面天然读写大量 `App` 字段（`a.page` / `a.tasks` / `a.lic` …）。
强行拆包要么把几十个字段导出、要么包一层巨大的接口——属于过度设计，且会让页面代码变成
`*h.Page = "task"` 这种噪音。Go 无法把「一个包」按目录切开，所以业务层用 `page_` 前缀做
显式归类，并在 README 的依赖方向一节写明这条取舍。

### 2.2 间距与等宽

新增 `internal/ui/kit/layout.go` 作为**间距唯一真源**：

| 常量 | 值 | 用在哪 |
| :--- | :--- | :--- |
| `PagePadX` / `PagePadY` | 28 / 24 | `shell.Content` 的滚动区 padding |
| `PageGap` | 16 | `shell.Content` 内部的 `Column.Gap`（区块间距） |
| `RowGap` | 16 | `kit.RowGrid` 的栅格间距 |
| `CardGap` / `CardPad` / `CardRadius` | 12 / 18 / 10 | `kit.Card` 内部 |
| `SettingsLabelWidth` / `LabelWidth` | 90 / 96 | 设置行 / 键值行标签宽度 |

关键改动（`shell/content.go`）：

```go
ui.Scroll(c).Grow(1).
    Padding(kit.PagePadY, kit.PagePadX).      // 页面四周留白，容器给
    TrackScroll(o.Scroll).
    Children(func() {
        ui.Column(c).Gap(kit.PageGap).Children(o.Body)  // 区块间距，容器给
    })
```

于是**页面函数只写区块**。改造中删除了各页面自带的 12 处垂直 padding。

等宽：新增 `kit.RowGrid(c, n, fn)` = `ui.Grid(c).Columns(n).Gap(RowGap)`。栅格列宽是
`Fr(1)` 严格等分，且网格项默认 `Stretch`（同一行自动等高）。替换清单：

- 首页 KPI 四卡：`Row+Grow` → `RowGrid(4)`
- 首页主体两栏：左 `Grow(1)` + 右 `Width(320).Shrink(0)` → `Grow(2)` / `Grow(1)`
- 异步任务两张任务卡：`Grid(2)` + Column 包裹 → `RowGrid(2)`
- 基本信息两栏、卡片演示三卡、输入演示两栏、标签页演示两栏 → `RowGrid`
- 单卡片区块的 `Row(...).Padding(16,0,0)` 包裹层 → 直接把 `kit.Card` 作为页面区块
  （顺带修掉一个隐性 bug：单卡片放在 Row 里宽度按内容算，并没有占满整行）

### 2.3 滚动条

- 删除 `t.Scrollbar = t.Scrollbar.Alpha(0)`（内容区恢复主题默认：悬停/拖动时显现）。
- 侧栏隐藏：`ui.Scroll(...).ScrollbarInsets(0, 400, 0, 0)`。mygo 的竖直滚动条 X =
  `box.X + box.W - right - width - 3`，右侧给 400 的内缩后 X 变为负数、落到窗口左边界之外，
  既不可见也不可点；而且 `paint.go` 里 `scrollbars(e)` 是在**节点裁剪之外**绘制的，所以不会
  被容器裁掉再"露出来"。取值与原因写在 `shell/layout.go` 的 `scrollbarHideInset`。
- 页头横向工具条同理（大 `bottom` 内缩把横条推到页头之上）。

## 五、遗留与后续

1. **侧栏滚动条隐藏无法用像素断言验证**：mygo 只在**鼠标悬停**容器时绘制滚动条，Tester
   没有 hover 注入，所以只能在真机上手移到侧栏上确认。若真机上仍看到侧栏滚动条，说明
   `scrollbarHideInset` 不足以推到窗口外，按同一公式加大即可（`box.W - inset - 9 < 0`）。
2. **网格等高带来的底部留白**：同一行两卡内容多少不同时，较矮的卡会被拉伸到等高，内部
   内容顶对齐，底部留少量空白。这是"等高"的必然代价，视觉上比参差更整齐。
3. 内容区滚动条是 overlay 式的（悬停/拖动才显现）。若希望"常驻可见"，需要改 mygo 的
   `paint.go`（`barsShown = hovered || dragging`）或改用自绘滚动条——属于框架层改动，
   未在本轮范围内。
